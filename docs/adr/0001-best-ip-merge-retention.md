# 优选 IP 合并保留而非整表覆盖

取数脚本原先每次 CloudflareSpeedTest 后整表覆盖 `cloudflare-result.csv`，一次波动就会丢掉仍可用的旧 IP。我们改为：复测上一轮 CSV 中的 IP，与本轮新测结果合并去重，按下载速度排序后截断到节点上限（部署环境变量 `BEST_IP_MAX`，默认 30）；不能连通或未达本轮阈值的条目不进入结果。

## Considered Options

- **整表覆盖**：实现最简单，但旧 IP 中仍合格的会被一次空窗丢弃，订阅质量抖动大。
- **合并保留 + 上限截断**：多一轮复测成本，换来节点集合更稳；超出上限时按速度排序淘汰。
- **无限累积历史 IP 池**：每轮全量复测成本无上界，且被挤出的 IP 多半已不合格，收益低。

## Consequences

- 「上一轮 IP」只回看最近一份 `cloudflare-result.csv`，不维护更长历史。
- 同一 IP 在两轮中都出现时，保留本轮测得速度更高（速度相同则延迟更低）的一条。
- 节点上限统一用 `BEST_IP_MAX`：本地脚本合并截断与订阅 `top` 默认值共用同一配置语义。
